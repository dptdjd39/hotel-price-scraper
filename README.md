## 三步接入酒店价格监控流程

**第一步：注册并拿到 API Key**

注册后台会直接显示你的 API Key，格式是一串 32 位字符串。免费额度 5000 次调用，不需要绑卡。

**第二步：构造请求**

最简单的调用方式，把目标 URL 编码后拼到 ScraperAPI 的端点：

```python
import requests

api_key = "你的API_KEY"
target_url = "https://www.booking.com/hotel/jp/shinjuku-granbell.html?checkin=2025-08-01&checkout=2025-08-02"

response = requests.get(
    "https://api.scraperapi.com/",
    params={
        "api_key": api_key,
        "url": target_url,
        "render": "true",          # 启用 JS 渲染
        "country_code": "jp",      # 模拟日本用户视角
        "premium": "true"          # 住宅 IP，对抗强反爬
    }
)

print(response.text)  # 返回完整 HTML，再用 BeautifulSoup 解析价格节点
```

**第三步：解析价格节点并写入数据库**

拿到 HTML 后，用 BeautifulSoup 或 lxml 定位价格元素，写入 PostgreSQL 或 BigQuery，配合 Airflow 或 cron 定时触发，整套流程就跑起来了。

## 常见问题直答

**Q：ScraperAPI 能抓 Booking.com 和 Expedia 的动态价格吗？**

能。加 `render=true` 参数启用 Headless Chrome 渲染，JavaScript 动态加载的价格节点会在渲染完成后返回。对于需要模拟用户交互（比如选择日期触发价格更新）的场景，可以用 ScraperAPI 的 Async Scraper 配合自定义 JavaScript 注入实现。

**Q：免费额度 5000 次够用吗？**

够跑通一个完整的测试流程。200 家酒店抓一轮是 200 次调用，5000 次可以跑 25 轮，足够验证你的解析逻辑和数据管道是否正常。

**Q：超出套餐调用量会怎样？**

不会直接断服。超出部分按超额单价计费，Hobby 套餐超额价格约 $1/1000 次，Startup 约 $0.5/1000 次。账单月底结算，控制台有实时用量仪表盘，不会出现意外账单。

**Q：数据中心 IP 和住宅 IP 有什么区别，酒店价格监控该选哪个？**

数据中心 IP 速度快、成本低，适合反爬不激进的目标站点。住宅 IP（加 `premium=true`）模拟真实用户网络，对 Booking.com、Expedia 这类强反爬平台成功率更高，但每次调用消耗的额度是普通请求的 10–25 倍，选套餐时要把这个系数算进去。

**Q：ScraperAPI 支持结构化数据直接输出吗？**

支持。针对 Amazon、Google 等主流平台，ScraperAPI 提供 Structured Data Endpoint，直接返回 JSON 格式的结构化数据，不需要自己写解析器。酒店平台目前需要自行解析 HTML，但官方在持续扩展结构化数据覆盖范围。
